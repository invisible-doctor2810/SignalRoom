# 1. PRODUCT VISION

## Product Name: SignalRoom
**Tagline:** Investigate together. Establish the facts. Understand what happened.

### Problem
When a technical incident occurs, investigations often become fragmented across logs, messages, screenshots, documents, and individual team members' observations.

This creates several problems:

- Evidence is scattered across multiple locations.
- Different investigators develop competing explanations.
- Important events are missed or recorded out of order.
- Conclusions are sometimes accepted without sufficient evidence.
- Teams struggle to reconstruct exactly what happened.

### Solution
SignalRoom is a collaborative incident investigation platform that provides a centralized workspace for investigating incidents.

Each incident has its own investigation room where authorized team members can:

1. Record incident details.
2. Collect and organize evidence.
3. Build chronological incident timelines.
4. Develop competing hypotheses.
5. Associate evidence with hypotheses.
6. Collaborate in real time.
7. Use an AI investigation assistant.
8. Generate a structured incident resolution report.

### Core differentiator
SignalRoom is NOT another AI chatbot.

Its primary differentiator is **evidence-grounded investigation**.

AI should distinguish between:

- Verified facts.
- Investigator observations.
- AI-generated hypotheses.
- Confirmed conclusions.
- Unresolved questions.
Every AI-generated factual claim must be traceable to an actual evidence record or timeline event.

AI must never fabricate evidence or present speculation as an established fact.

Human investigators retain control over final conclusions.

# 9. AI INVESTIGATION ASSISTANT
This feature must provide genuine product value.

Do not build a generic chatbot with an incident-themed system prompt.

Build an investigation assistant that understands the structured context of an incident.

### Context provided to the AI
The server should retrieve:

- Incident description.
- Relevant timeline events.
- Evidence records.
- Existing hypotheses.
- Evidence-hypothesis relationships.
- Investigator observations.
Only provide data belonging to the currently authorized incident.

### AI capabilities
The assistant should support:

1. Incident summarization.
2. Potential explanations.
3. Supporting evidence identification.
4. Contradicting evidence identification.
5. Missing information detection.
6. Suggested next investigation steps.
7. Resolution report drafting.

### Structured AI response
Use a structured response format containing:

- summary
- establishedFacts
- hypotheses
- supportingEvidence
- contradictingEvidence
- missingInformation
- recommendedActions
- uncertainty
Every evidence reference must correspond to a real evidence ID retrieved from the current incident.

The backend must validate all references before presenting them as citations.

AI must distinguish between:

- What the evidence establishes.
- What the evidence suggests.
- What remains unknown.
Never fabricate evidence, timestamps, investigators, or incident events.

AI suggestions must require human review before becoming official investigation conclusions.

### AI interface
Create a dedicated analyst panel with:

- Conversational interface.
- Suggested investigation questions.
- Structured findings.
- Evidence references.
- Loading states.
- Error handling.
- Clear distinction between suggestions and verified facts.
Use DeepSpace-native AI capabilities wherever appropriate.

If additional model configuration is required, explain it before introducing external dependencies.
